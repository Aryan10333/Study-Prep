## 3. Per-Notebook Real Experiments

**Notebook 01 — Real Automated Metrics vs. Real Human-Style Correctness Labels**
- Real `gpt-4o-mini` calls generating answers to a real, small set of factual questions, at varying real phrasings/temperatures to produce genuine paraphrase variety (extending Module 01's 5-paraphrase illustration to a larger real, generated set).
- Compute real BLEU-1/ROUGE-1 scores against a reference for each real generated answer. **Correctness labeling uses a rigorous, stated protocol, not informal "direct fact-checking"**: each question has one authoritative real reference source (e.g., a specific, cited real fact) fixed *before* generation; a real answer is labeled correct only if it states a claim that matches that authoritative source's real fact under an explicit, stated pass/fail rule (e.g., the core factual claim must be present and not contradicted — a real, defensible, reproducible criterion, not subjective judgment applied after the fact).
- Real, exploratory test of Module 02's central claim at larger scale than the module's own hand-worked 2-sentence example: does real n-gram overlap actually correlate with real correctness across a genuine generated sample? **Given this notebook's real sample size is necessarily small, any correlation finding is explicitly reported as exploratory, not a statistically robust conclusion** — the module's own small counterexample remains the notebook's real, verified anchor regardless of whether this larger, real sample's correlation trend is statistically stable.

**Notebook 02 — Real LLM-as-Judge: Position Bias & Calibration**
- Real `gpt-4o-mini` judge calls comparing real pairs of model responses (varying quality, generated in this same notebook), in both original and order-swapped presentation — a real, direct empirical measurement of Module 03's position-bias flip rate, not a constructed example.
- **Calibration made genuinely independent of the judge model**: the comparison ranking the judge is checked against is *not* generated by another LLM call (which would risk evaluating one model's judgment against another's, rather than against an independent quality signal). Instead, the real response set is constructed with a real, objective, pre-determined quality ordering — e.g., deliberately varying response quality via a real, verifiable, non-LLM-judged property (such as Notebook 01's rigorous correctness-labeling protocol applied to each response, or a real, fixed rubric-based rule checkable by direct inspection) — giving a genuinely independent real ground truth to compute Spearman correlation against, extending Module 03's constructed example without confounding the judge's own real calibration check with a second judge's opinion.

**Notebook 03 — Real LLM-Rater Agreement Across Two Independent LLM Raters**
- Two real, independently-prompted `gpt-4o-mini` "rater" calls labeling the same real set of responses pass/fail against a rubric. **Named and reported throughout as real LLM-rater agreement, never "inter-annotator agreement"** — two independent LLM raters measure a genuinely different real thing than human inter-annotator agreement (Module 04's actual real scope), and this notebook does not claim otherwise or use human-evaluation terminology for it.
- Compute real Cohen's kappa on the real resulting 2-rater confusion table, extending Module 04's constructed 20-item example to genuine, live-generated LLM-rater ratings — explicitly framed as a real, adjacent exercise in agreement measurement, not a substitute for or a proxy claimed equivalent to real human annotation.

**Notebook 04 — Real RAG Faithfulness/Context Precision-Recall + Agent Efficiency**
- A real, small RAG pipeline (reusing a real, simple retrieval setup in the spirit of `03_advanced_rag`'s own notebooks, not re-deriving that topic's retrieval-construction content) answering real questions against a real small document set.
- Real, direct claim-by-claim faithfulness checking of generated answers against real retrieved context. **Context precision/recall computed against an explicit, real ground-truth relevance set defined before retrieval runs**: for each real query, every chunk in the small real document set is pre-labeled relevant/non-relevant against that query under Module 05's own stated rubric (necessary to support the real correct answer) — retrieved chunks alone are not sufficient to compute real precision/recall, since both metrics require knowing the full real relevant set, not just what was retrieved.
- A real, simple tool-using agent loop (reusing patterns from `04_ai_agents_and_protocols`'s own notebooks, not re-deriving agent-architecture content) logging real tool-call count/tokens/latency/cost across a few real task runs, to test whether Module 05's "efficiency varies even at equal success" finding reproduces with genuine agent execution.

**Notebook 05 — Real Hallucination Detection: Self-Consistency vs. Grounded Verification**
- Real $k$-sample self-consistency checks (multiple real `gpt-4o-mini` calls per question) on a real set of factual questions, computing real agreement rates.
- **Grounded verification uses a real, independent source — not the same generation model.** Verifying a claim by asking the identical model that generated it risks the verification reproducing the same real underlying error, which would not constitute a genuine, independent factuality check. The real verification step instead performs a direct real lookup/search against a real, separate reference source (e.g., a real, authoritative real-world reference distinct from the generation model's own weights) — the module's actual real "independent evidence" requirement, not merely a second LLM call.
- **The "wrong but self-consistent" criterion is defined and fixed before running any experiment**, not chosen after seeing results: a real trial counts as this failure pattern only if (a) self-consistency agreement across $k$ samples exceeds a real, pre-stated threshold (e.g., ≥0.7), AND (b) the real, independent grounded-verification step returns a contradiction against the majority-agreed answer — both criteria stated in advance, preventing the real, honest risk of cherry-picking examples after the fact to manufacture a confirming result.

Real, direct empirical test of Module 06's central claim: does real high self-consistency ever coincide with a real, independently-grounded-verification-confirmed wrong answer, as Module 06's constructed Scenario A predicts is possible — reported honestly whether or not the pre-defined criterion above is actually met by any real trial.

**Notebook 06 — Real Guardrail Classifier + Production Capstone**
- A real, small pretrained Hugging Face safety/toxicity classifier run locally on the RTX 4060, evaluated for real precision/recall/F1 on a real small labeled test set. **Threshold selection follows a principled, stated method, not an arbitrary choice**: real precision/recall/F1 computed across a real swept range of decision thresholds, with the specific real threshold used in later cells chosen via an explicit, stated criterion (e.g., the threshold maximizing real F1, or a real threshold meeting a stated minimum-recall requirement given this notebook's own real, chosen cost framing for false negatives vs. false positives) — extending Module 08's constructed two-threshold illustration to a genuine, systematically-searched real trade-off curve, not just an arbitrary pair of points.
- **Real measured sequential vs. parallel latency uses genuinely independent checks**, not two calls to the same classifier or checks with a real data dependency between them (e.g., toxicity classification and a real, separate PII-detection check that don't depend on each other's output) — ensuring the real measured parallel-latency benefit reflects real guardrail-stack architecture, not merely orchestration/scheduling overhead from artificially separated calls to a single check.
- **Capstone, explicitly split into two separate real experiments, not blended**: (1) a real, constructed multi-step pipeline trace (reusing this notebook's own real RAG/agent/classifier calls from earlier cells) logged with real per-span timing and status, applying Module 07's root-cause-localization function to diagnose one specific, individual real request's failure — a per-request diagnostic exercise; (2) separately, a real before/after evaluation-set-versioning comparison (Module 09) using this notebook's own real generated outputs scored under two real, deliberately different reference-answer sets — an aggregate, system-level evaluation-behavior exercise. These remain two distinct real experiments within the capstone because they answer genuinely different real questions (one request's failure vs. aggregate system behavior over an evaluation run), not merged into one blended demonstration.

## 4. Real vs. Illustrative Labeling Discipline

Every notebook is real, live-API/real-model execution (no illustrative-only notebook), using the four-tier labeling scheme established in `06_llm_inference_and_optimization`'s own Track 2: `[REAL]` for genuine API/model execution and measurement, `[COMPUTED FROM REAL DATA]` for formulas evaluated on genuine notebook-generated inputs, `[SIMULATION]` for any deliberately constructed exercise, `[EXPLANATION]` for prose-only cells. **`[SIMULATION]` applies specifically to Notebook 06's deliberately constructed version/drift scenarios (the two different reference-answer sets, the before/after comparison) — using real model outputs as inputs does not make a deliberately constructed production scenario a real observed production event**, and this distinction is stated explicitly rather than let the presence of real outputs imply the scenario itself was organically observed. Any technique that proves infeasible on real live execution (e.g., a genuine grounded-verification source not returning a usable real answer) will be reported honestly as a real, encountered constraint, with a graceful, clearly-labeled real fallback — never a fabricated result.
